This website aims mainly at providing RF test data for the PLUTO-like SDR platforms based on Zynq FPGA 7010/7020 and AD9363/61 RFIC. 
I was originally looking at the LibreSDR and I struggled to find anything showing the performance of this device in a 
controlled environment, therefore decided to do it myself.

Firmwares
----------------------

Default firmware
~~~~~~~~~~~~~~~~~~~~

By default the clones ship with an unknown firmware based on the PlutoSDR firmware v0.37 or above, dubbed **"v0.xx-dirty"**.
This "dirty" default firmware seems to be quite limited and not supported so users tend to replace it with an alternative one, the most famous being Tezuka's (see below)

Alternative firmwares
~~~~~~~~~~~~~~~~~~~~~

Most users seem to switch to alternative firmwares. Among the most popular ones:

- :guilabel:`Tezuka` from F5OEO: https://github.com/F5OEO/tezuka_fw
    This firmware is built in many different versions (for different platforms) and adds many new functionalities, as well as support for other open-source projects such as Maia SDR

- :guilabel:`libresdr` from hz12opensource: https://github.com/hz12opensource/libresdr
    This firmware focuses mainly on LibreSDR and overclocking and increasing continuous sampling rate

These two repositories contain convenient SD card images: 

#. Format an SD card in FAT32
#. Simply extract the content of the release ZIP file onto the SD card

    .. figure:: assets/figures/sd_card.png
        :align: center
        :scale: 60 %

        SD card preparation

#. Insert it in the LibreSDR and plug it in: the SDR will boot from the SD card instead of the internal flash. The device will appear as an external drive (as usual). Open ``info.html`` and confirm you are running the correct fw (In this example: Tezuka):

    .. figure:: assets/figures/tezuka_info.png
        :align: center
        :scale: 60 %

        Checking Tezuka has booted

This method has the advantage that the internal flash remains untouched, eliminating the risk of bricking the device.

.. _extended_cap:

"Extended capabilities"
------------------------

An AD9363-based device can be set as an AD9364/61 for extended capabilities.
The ADI :guilabel:`Customization` page (see link above) explains the different possible configurations and commands to use.
The process is also summarised here.

Configuration
~~~~~~~~~~~~~~~

- Plug the device to your computer using the USB port. Windows should enumerate a COM port

    .. figure:: assets/figures/pluto_com.png
        :align: center
        :scale: 80 %

        COM port

- Connect to that serial port using a tool like TeraTerm or similar with the settings :guilabel:`9600,N,8,1`

- Connect to the device with :guilabel:`username: root` and :guilabel:`password: analog` or :guilabel:`password: root` (for the "dirty" fw). You will be welcome with a prompt:

    .. figure:: assets/figures/linux_default_welcome.png
        :align: center
        :scale: 80 %

        Welcome prompt

- Type the following commands:

    .. code-block::

        fw_setenv attr_name compatible
        fw_setenv attr_val <rfic>
        fw_setenv compatible <rfic>
        fw_setenv mode <mode>
        reboot

    The options for ``<rfic>`` and ``<mode>`` are given in the Modes section below

    You can get the current state of the device by typing:

        .. code-block::

            fw_printenv attr_name
            fw_printenv attr_val

    For example if you get:

        .. code-block::

            fw_printenv attr_name
            --> Error: "attr_name" not defined
            fw_printenv attr_val
            --> Error: "attr_val" not defined

    It means those attributes are not defined, the device is therefore in AD9363 mode. This should be the default state.

Available Modes
~~~~~~~~~~~~~~~~

+----------------+------------------------+-----------------+---------------+--------------------+
| <rfic>         | <mode>                 | LO tuning range | Max bandwidth |  Max sampling rate |
+================+========================+=================+===============+====================+
| AD9363         | 1r1t (1x RX + 1x TX)   | 325 - 3800 MHz  | 20 MHz        |  61.44 Msps        |       
+                +------------------------+-----------------+---------------+--------------------+
|                | 2r2t (2x RX + 2x TX)   | 325 - 3800 MHz  | 20 MHz        |  30.72 Msps        |       
+----------------+------------------------+-----------------+---------------+--------------------+
| AD9364         | 1r1t (1x RX + 1x TX)   | 70 - 6000 MHz   | 56 MHz        |  61.44 Msps        |       
+----------------+------------------------+-----------------+---------------+--------------------+
| AD9361         | 1r1t (1x RX + 1x TX)   | 70 - 6000 MHz   | 56 MHz        |  61.44 Msps        |       
+                +------------------------+-----------------+---------------+--------------------+
|                | 2r2t (2x RX + 2x TX)   | 70 - 6000 MHz   | 56 MHz        |  30.72 Msps        |       
+----------------+------------------------+-----------------+---------------+--------------------+

Example, to put the device in AD9361 / 2r2t mode, type:

.. code-block::

        fw_setenv attr_name compatible
        fw_setenv attr_val ad9361
        fw_setenv compatible ad9361
        fw_setenv mode 2r2t
        reboot

Enabling Ethernet
---------------------

By default ethernet is disabled on Pluto Clones. Here is the procedure to enable it

1. Connect your pluto to your PC using an ethernet cable or a usb-to-ethernet adapter:

    .. figure:: assets/figures/setup_ethernet.svg
        :align: center
        :scale: 70 %

        Ethernet connections

    You also need to plug the USB port

2. When your pluto has enumerated, open `config.txt` and under the :guilabel:`USB_ETHERNET` section enter an IP address and corresponding mask. In my example I am using `192.168.3.1`. You can also see the default `192.168.2.1` under the :guilabel:`NETWORK` section, used by the USB port (and not the ethernet port):

    .. figure:: assets/figures/pluto_config.PNG
        :align: center
        :scale: 70 %

        Ethernet configuration SDR side

3. Then you need to configure your PC to match the same netmask. 

    - Assuming you are using a USB-to-Ethernet adpater (which I recommend), find its adpater in the windows settings (`Control Panel > Network and Internet > Network Connections`)
    - `Right-click > Properties > Internet Protocol Version 4`
    - Enter the correct mask and a valid IP address for that mask: eg `192.168.3.10`

    .. figure:: assets/figures/ethernet.PNG
        :align: center
        :scale: 70 %

        Ethernet configuration PC side

4. Close config.txt and eject the mounted drive (not the controller!) for the change to take effect. To be sure, once you've done that unplug the SDR and plug it back in: you should see your change

5. You can now connect to your SDR through the ethernet port. Eg in python:

    .. code-block:: python
 
        # Assuming you have pip-installed pyadi-iio
        # Assuming you have put your SDR in AD9361 mode

        import adi
        sdr = adi.ad9361("ip:192.168.3.1")

        # do stuff
        # ...

        sdr.close()
